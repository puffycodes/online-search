# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A collection of small, standalone Python scripts that each pull live data from a public web API (weather, air quality, stock prices, Hacker News and Lobsters, web search), plus matching Claude Code subagent definitions in `.claude/agents/` that let Claude call those scripts as tools and report results conversationally. There is no local package — every script is a self-contained `.py` file at the repo root, importable and runnable directly. A few scripts share small helper modules (`yahoo_finance.py`, `weather.py`, `hn.py`, `lobsters.py`, `indicators.py`, `valuation.py`, `cli_utils.py`) instead of duplicating logic.

**All code was originally generated by Claude and is unverified — treat correctness claims in docstrings/README skeptically and verify against actual behavior when it matters.**

## Commands

```bash
# Runtime deps (per-script; matplotlib only needed for the two chart scripts)
pip install requests
pip install matplotlib          # stock_candlestick_chart.py, stock_rebased_chart.py
pip install beautifulsoup4      # url_content.py --text mode, url_links.py and url_metadata.py (always)

# Test deps
pip install -r requirements-dev.txt   # pytest + requests

# Run the full suite (offline — every network call is monkeypatched)
python3 -m pytest

# One module / one test / by keyword
python3 -m pytest tests/test_valuation.py
python3 -m pytest tests/test_valuation.py::TestDiscountedCashFlow::test_basic
python3 -m pytest -k "build_params"

# Quieter / verbose-stop-on-first-failure
python3 -m pytest -q --no-header
python3 -m pytest -x -vv
```

Any script or test must be run **from the repo root** — nothing is pip-installed, so imports of sibling modules (`import weather`, `import cli_utils`, `from yahoo_finance import ...`) only resolve when the repo root is on `sys.path`. `pytest.ini` sets `testpaths = tests`; the root `conftest.py` prepends the repo root to `sys.path` so tests can `import` the scripts under test.

Commands, docs and agents all use `python3`. On Windows that only works if `python3` is a real interpreter rather than the Microsoft Store alias, which prints "Python was not found…" and exits 9009 (49 from Git Bash). The working setup is a `python3.exe` copied next to `python.exe` in the active virtualenv's `Scripts\` (see the Windows note at the top of `README.md`). If `python3` fails that way, say so and fall back to `python`; don't switch the repo's commands to `python`.

There is no linter or formatter configured in this repo — don't invent a lint/format step in instructions to the user.

## Architecture

### Standalone-script-with-shared-helpers pattern

Every user-facing tool is one file at the repo root runnable as `python3 <script>.py ...`. Where several scripts need the same fetch/parse logic, that logic is pulled into a shared, non-CLI helper module imported directly (not shelled out to):

- **`yahoo_finance.py`** — shared by `stock_price_history.py`, `stock_candlestick_chart.py`, `stock_rebased_chart.py`: the Yahoo chart-endpoint URL/headers/timeout constants, `add_window_args()` (declares the `--range`/`--last`/`--start`/`--end` flags), `build_params()` (turns them into query params), `fetch_history()`, `extract_series()`, `meta_summary()`, `session_datetime()` (exchange-local session dates, also used by `app/stock_information/`). It also holds the cookie + crumb handshake (`fetch_crumb()`, `crumb_session()`) used by `market_top_volume.py`, and the `quoteSummary` fetch built on it (`fetch_quote_summary(symbol, modules)`, plus the `summary_num()`/`summary_text()` readers) used by `stock_intrinsic_value.py`, `stock_earnings_calendar.py`, `stock_analyst_targets.py` and `stock_holders.py` (and, through `stock_intrinsic_value.fetch_fundamentals()`, by `stock_fundamental.py`). Each script keeps its own row shaping (rounding, which fields to keep, which rows to drop) and its own output/render stage. **Changing a constant or the window-building logic here affects all three price scripts; changing the crumb handshake affects every crumb user.**
- **`weather.py`** — shared by `weather_forecast.py`, `weather_history.py` and `air_quality.py`: `geocode()` (Open-Meteo geocoding), `fetch_json()` (surfaces Open-Meteo's error `reason`), `format_place()`, `place_fields()` (the location fields every record starts with), and (for the forecast and history scripts) `weather_description()` plus the daily-series helpers `daily_value()`, `sun_fields()` (local sunrise/sunset, daylight, polar night/day), `format_sun()` and `format_daylight()`.
- **`hn.py`** — shared by `hottest_tech_discussions.py`, `hn_search.py` and `hn_thread.py`: `fetch_json()` (surfaces the Algolia API's error `message`), `fetch_story()` (one item from the official HN API, `None` on failure), `fetch_hottest()` (the top stories by score from a 4× candidate pool), `discussion_url()` (also used by `stock_tech_buzz_agent.py`), `posted_at()`, and `clean_text()` (HN's HTML comment/self-post text to plain text, with the shared `TEXT_CHARS` default cut).
- **`lobsters.py`** — shared by `hottest_tech_discussions.py` (its `lobsters` source) and `lobsters_thread.py`: `LOBSTERS_BASE`, `HEADERS`, `fetch_page()` / `fetch_hottest()` (the front-page feeds, with tag exclusion) and `posted_at()` (Lobsters' offset time to UTC).
- **`indicators.py`** and **`valuation.py`** — dependency-free, pure-function libraries (no I/O) used by the chart scripts, `stock_intrinsic_value.py`, and the `stock-trend` agent. Plain-English write-ups of both live in `docs/`.
- **`cli_utils.py`** — cross-cutting CLI helpers used by nearly every script: `use_utf8_output()`, called first in every script's `main()` so piped output is UTF-8 on Windows too (without it, non-cp1252 characters crash the script), `die(message, as_json)` for uniform error-exit, `validate_url_scheme(url, as_json)` for the `http://`/`https://` check shared by the four `url_*.py` scripts, `response_text(response)` for decoding a fetched page correctly when the server names no charset (used by `url_content.py`, `url_links.py`, `url_metadata.py`), `positive_int` / `non_negative_int` / `bounded_int(maximum)` argparse types, `load_dotenv()` for `.env`-based API key loading, `require_env(name, script, as_json)` for the API-key check (scripts call `load_dotenv()` first, keeping it patchable in tests), and `format_result()`/`print_results()` for the shared `{rank, title, url, snippet}` shape used by six of the seven `web_search_*.py` scripts (all but `web_search_perplexity.py`).
- **`stock_tech_buzz_agent.py`** and **`app/hottest_discussions/hottest_discussions_server.py`** import `market_top_volume.py` / `hottest_tech_discussions.py` directly rather than shelling out, for the same reason. Likewise **`app/stock_information/stock_info_server.py`** imports `yahoo_finance.py`, `stock_price_history.py`, `stock_intrinsic_value.py` and `stock_fundamental.py` (which itself reuses `stock_intrinsic_value.py`'s fetch and parsing). Both apps are small `http.server` servers (default ports 8000 and 8001) so their pages run the repo's Python instead of re-implementing it in JavaScript. **`url_content.py`** imports `url_metadata.extract_metadata()` for its `--text` `title`, so the two scripts read titles by the same rules. `hottest_tech_discussions.py` takes `--source hn|lobsters` (default `hn`): each source is ranked and reported separately because the scores aren't comparable, and `get_hottest_tech_discussions()` stays Hacker News only for its two importers.

When adding a new script that overlaps an existing one, prefer extending the shared module over copy-pasting — that's the established pattern here.

### The `--json` convention

Every CLI script that an agent calls supports a `--json` flag: with it, the leading human progress line is suppressed and the result prints as a single JSON object/array on stdout; without it, a formatted human-readable report prints instead. **On failure, the exit code is 1 and the error goes to stderr** — as `{"error": "..."}` with `--json`, or a plain `Error: ...` line otherwise. Argparse-level failures (bad flag values, mutually exclusive flags used together) exit with code **2** instead, before any network call. This split (1 = runtime/data failure via `cli_utils.die()`, 2 = argument-parsing failure) is load-bearing for the test suite and for how agents decide whether to retry.

### Agent layer (`.claude/agents/*.md`)

Each subagent is a thin conversational wrapper around exactly one (or a small, fixed chain of) underlying script(s), invoked via the `Bash` tool with `--json`, parsing stdout, and reporting a summary — never fabricating data the script didn't return. Conventions to preserve when adding or editing an agent:
- Frontmatter `tools:` is scoped to the minimum needed (`Bash` alone for most; `Bash, Read` for the two chart agents, which also read back the generated PNG to confirm it rendered).
- A "no location/ticker found"-type result is reported as-is; a transient-looking network failure is retried **at most once**.
- Chart agents always render to an explicit `/tmp/...` path (never `--show`, never writing into the repo) and return the absolute PNG path on its own line for the caller to display.
- The `web-search` agent chains through six `web_search_*.py` scripts in a fixed fallback order (Brave → Serper → Tavily → SerpApi → Exa → DuckDuckGo) based on which API key is present/working, stopping at the first success; `web_search_perplexity.py` is deliberately excluded from that chain because its output shape (synthesized answer + sources) doesn't match the others' flat `[{rank, title, url, snippet}, ...]`.
- Subagent definitions are loaded at session start — a new or edited `.claude/agents/*.md` file only takes effect in sessions started **after** the edit, not the current one.

### Test layer (`tests/`)

Fully offline: every HTTP call is monkeypatched at the seam closest to the boundary (e.g. `monkeypatch.setattr(yf.requests, "get", ...)`, `monkeypatch.setattr(weather, "fetch_json", ...)`). `tests/helpers.py` provides `FakeResponse`/`FakeSession` duck-types of `requests.Response`/`requests.Session`; `tests/conftest.py` holds the shared `chart_result` fixture (a well-formed Yahoo chart `result` block). Test files mirror module names 1:1 (`foo.py` → `tests/test_foo.py`), grouped into `class Test<Thing>` per behavior. `main()` is tested by calling it directly with an argv list and asserting on `capsys` + `SystemExit.code`, not by spawning a subprocess. Agents, being prompts, aren't covered by the suite; the multi-step `hottest-tech-discussion-summary` agent instead has targeted live runs in `docs/features/agent/hottest-tech-discussion-summary/test-runs.md` (a fixed topic per edge-case rule, with pass criteria), to rerun after editing that agent and to extend when a run finds a new edge case. See `tests/README.md` for the full per-module coverage table and conventions before adding a test.

### Documentation is kept in lockstep with code

`README.md` documents every script and every agent in matching sections (Requirements / Usage / Example / How it works / Configuration / API reference / Error handling / Notes-limitations), and `tests/README.md` keeps a per-module coverage table current. When adding or changing a script, agent, or test module, update both README files in the same change — this repo's history treats that as part of the same commit, not a follow-up.

Each runnable script, agent and web app also has a feature spec in the same Requirement / Actions / `{{placeholder}}` format: `docs/features/script/<script_name>/features.md` (one per root `.py` with a CLI; the helper modules have none), `docs/features/agent/<agent-name>/features.md` (one per `.claude/agents/*.md`), and `app/<app>/docs/features.md`. The web apps were built from their specs — when asked to "update the app in .../features.md", diff the spec against the last commit and implement the change. The script and agent specs were written afterwards from the code; when a script or agent changes, update its spec in the same change. Agent specs live under `docs/` rather than `.claude/agents/` because every `.md` file there is loaded as an agent.

## Key domain notes worth knowing before touching the code

- **Yahoo Finance and the market-screener endpoints are unofficial/undocumented** (chart endpoint, screener endpoint, quoteSummary). They can change without notice; the crumb/cookie handshake (`yahoo_finance.fetch_crumb()`, used by `market_top_volume.py` and, through `fetch_quote_summary()`, by `stock_intrinsic_value.py`, `stock_fundamental.py`, `stock_earnings_calendar.py`, `stock_analyst_targets.py` and `stock_holders.py`) is the most fragile part.
- **US AQI and European AQI are not comparable** — different breakpoints/scales; `air_quality.py` and its agent deliberately never average or combine them.
- **Tickers are Yahoo notation**, including exchange suffixes for non-US listings (`.L`, `.SI`, `.DE`, `.PA`, `.TO`, `.AX`, `.NS`, `.HK`, `.T`, …) — none of the stock scripts resolve company names to tickers themselves; that resolution happens in the agent layer's judgment. The chart-endpoint scripts (`stock_price_history.py` and the two chart scripts) also take Yahoo's non-equity symbols — indices (`^GSPC`), currency pairs (`EURUSD=X`), crypto (`BTC-USD`), front-month futures (`GC=F`) — and their agents say so; the `quoteSummary` scripts (fundamentals, intrinsic value, earnings calendar, analyst targets, holders) only make sense for company stocks.
- **`indicators.py`/`valuation.py` outputs are descriptive/mechanical, not predictive** — `trend()` is a straight-line fit, DCF/multiple valuations are pure arithmetic over caller-supplied assumptions. Don't let agent-facing text overstate them as forecasts or advice.
