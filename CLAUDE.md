# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A collection of small, standalone Python scripts that each pull live data from a public web API (weather, air quality, stock prices, Hacker News, package vulnerabilities, web search), plus matching Claude Code subagent definitions in `.claude/agents/` that let Claude call those scripts as tools and report results conversationally. There is no local package — every script is a self-contained `.py` file at the repo root, importable and runnable directly. A few scripts share small helper modules (`yahoo_finance.py`, `price_source.py`, `daily_prices.py`, `weather.py`, `hn.py`, `indicators.py`, `valuation.py`, `robots.py`, `cli_utils.py`) instead of duplicating logic.

**All code was originally generated by Claude and is unverified — treat correctness claims in docstrings/README skeptically and verify against actual behavior when it matters.**

## Commands

```bash
# Runtime deps (per-script; matplotlib only needed for the two chart scripts)
pip install requests
pip install matplotlib          # stock_candlestick_chart.py, stock_rebased_chart.py
pip install beautifulsoup4      # url_content.py --text mode, url_links.py, url_metadata.py and url_feed.py (always)
pip install defusedxml          # url_feed.py (safe parsing of untrusted feed XML)

# Test deps
pip install -r requirements-dev.txt   # pytest + requests

# Run the full suite (offline — every network call is monkeypatched)
python3 -m pytest

# One module / one test / by keyword
python3 -m pytest tests/test_valuation.py
python3 -m pytest tests/test_valuation.py::TestDiscountedCashFlow::test_basic
python3 -m pytest -k "build_params"

# Quieter / verbose-stop-on-first-failure
python3 -m pytest -q --no-header
python3 -m pytest -x -vv
```

Any script or test must be run **from the repo root** — nothing is pip-installed, so imports of sibling modules (`import weather`, `import cli_utils`, `from yahoo_finance import ...`) only resolve when the repo root is on `sys.path`. `pytest.ini` sets `testpaths = tests`; the root `conftest.py` prepends the repo root to `sys.path` so tests can `import` the scripts under test.

Commands, docs and agents all use `python3`. On Windows that only works if `python3` is a real interpreter rather than the Microsoft Store alias, which prints "Python was not found…" and exits 9009 (49 from Git Bash). The working setup is a `python3.exe` copied next to `python.exe` in the active virtualenv's `Scripts\` (see the Windows note at the top of `README.md`). If `python3` fails that way, say so and fall back to `python`; don't switch the repo's commands to `python`.

There is no linter or formatter configured in this repo — don't invent a lint/format step in instructions to the user.

## Architecture

### Standalone-script-with-shared-helpers pattern

Every user-facing tool is one file at the repo root runnable as `python3 <script>.py ...`. Where several scripts need the same fetch/parse logic, that logic is pulled into a shared, non-CLI helper module imported directly (not shelled out to):

- **`yahoo_finance.py`** — shared by `stock_price_history.py`, `stock_candlestick_chart.py`, `stock_rebased_chart.py`, `stock_risk.py`: `add_window_args()` (declares the `--range`/`--last`/`--start`/`--end` flags), `build_params()` (turns them into query params), `extract_series()`, `meta_summary()`, `session_datetime()` (exchange-local session dates, also used by `app/stock_information/`). The price scripts no longer call Yahoo: they fetch through `price_source.fetch_history()`, which returns the same chart-result shape. The chart-endpoint constants and `fetch_history()` remain for `app/stock_information/`'s quote. It also holds the cookie + crumb handshake (`fetch_crumb()`, `crumb_session()`) used by `market_top_volume.py`, and the `quoteSummary` fetch built on it (`fetch_quote_summary(symbol, modules)`, plus the `summary_num()`/`summary_text()` readers) used by `stock_intrinsic_value.py` and `stock_holders.py` (and, through `stock_intrinsic_value.fetch_fundamentals()`, by `stock_fundamental.py`), and it is the Yahoo adapter behind `stock_data.py` (`analyst_view()` / `parse_analyst_view()` for `stock_analyst_targets.py`, `earnings_view()` / `parse_earnings_view()` for `stock_earnings_calendar.py`). Each script keeps its own row shaping (rounding, which fields to keep, which rows to drop) and its own output/render stage. **Changing a constant or the window-building logic here affects all four price scripts; changing the crumb handshake affects every crumb user.**
- **`price_source.py`** — the price scripts' data source since 2026-10-21: `fetch_history(symbol, params)` routes a Yahoo-notation ticker to EODHD (`EODHD_EXCHANGES`, indices `^X` → `X.INDX`, `EURUSD=X` → `EURUSD.FOREX`, `BTC-USD` → `BTC-USD.CC`) or, for India (`.NS`/`.BO`), Alpha Vantage (`.BSE`); refuses Singapore (`.SI`), Tokyo (`.T`) and futures (`=F`) for now; translates `yahoo_finance.build_params()` output to dates; builds weekly/monthly bars from daily ones; spaces Alpha Vantage calls 1.1 s apart; and returns the chart-result shape `yahoo_finance.extract_series()` parses, with `meta.source` and `meta.notes` (free-plan limits) that the scripts surface. It reuses the two scripts below for the fetches.
- **`stock_data.py`** — the provider-neutral facade the stock scripts are moving behind (step 1 of the "Proposed design" in `docs/things-to-explore.md`): each function returns plain dicts (ISO dates, fractions, `None` for missing, `source`/`notes`) and `PROVIDERS` routes it to an adapter module. Only `analyst_view()` and `earnings_view()` so far, served by `yahoo_finance.py` and used by `stock_analyst_targets.py` and `stock_earnings_calendar.py`, which no longer read Yahoo's structures. A script moved behind it keeps its output unchanged; its tests patch `stock_data.<function>` with neutral dicts, the adapter's parsing is tested in the adapter's test module, and `tests/test_stock_data.py` holds a contract test each new adapter should be added to.
- **`daily_prices.py`** — shared by `eodhd_price_history.py` and `alphavantage_price_history.py`, the keyed price scripts behind `price_source.py`: the `--start`/`--end`/`--last` flags and `resolve_window()`, `price_row()` (the same `{date, open, high, low, close, adj_close, volume}` row as `stock_price_history.py`), `in_window()` and `print_table()`. It deliberately doesn't import `yahoo_finance.py`. Each script takes its provider's own ticker notation (`AAPL.US` / `TSCO.LON`), reads its key from `.env` (`EODHD_API_KEY`, `ALPHAVANTAGE_API_KEY`), and redacts the key from error messages. Free tiers are tiny (EODHD 20 calls/day, 1 year; Alpha Vantage 25/day, 100 sessions), so live checks should be few.
- **`trip_weather.py`** — merges the other weather scripts by date for a trip (a place and up to 31 days, up to a year ahead), importing them rather than shelling out: `weather_forecast.fetch_daily_forecast(start=, end=)` and `forecast_day()` within the 16-day forecast, `weather_history.fetch_daily_history()` for typical weather (the same dates in past years, averaged, always labelled "not a forecast") beyond it, and `air_quality.fetch_hourly_air_quality()` / `daily_maxima()` while air quality is forecast (about 4–5 days, pollen about 3).
- **`weather.py`** — shared by `weather_forecast.py`, `weather_history.py` and `air_quality.py`: `geocode()` (Open-Meteo geocoding), `fetch_json()` (surfaces Open-Meteo's error `reason`), `format_place()`, `place_fields()` (the location fields every record starts with), and (for the forecast and history scripts) `weather_description()` plus the daily-series helpers `daily_value()`, `local_daily()` (moves sunrise/sunset to each date's own UTC offset: Open-Meteo applies today's offset to every date, an hour out across daylight saving; needs `zoneinfo` / `tzdata`), `sun_fields()` (local sunrise/sunset, daylight, polar night/day), `format_sun()` and `format_daylight()`.
- **`hn.py`** — shared by `hottest_tech_discussions.py`, `hn_search.py` and `hn_thread.py` (and `url_feed.py`, for `clean_text()` on feed summaries): `fetch_json()` (surfaces the Algolia API's error `message`), `fetch_story()` (one item from the official HN API, `None` on failure), `parse_item_id()` (an item id from a number or an HN link, for `hn_thread.py`'s `ITEM` and `hn_search.py`'s `--story`), `discussion_url()`, `posted_at()`, and `clean_text()` (HN's HTML comment/self-post text to plain text, with the shared `TEXT_CHARS` default cut).
- **`indicators.py`** and **`valuation.py`** — dependency-free, pure-function libraries (no I/O) used by the chart scripts, `stock_risk.py` (`volatility()`, `max_drawdown()`, `correlation()`), `stock_intrinsic_value.py`, and the `stock-trend` agent. Plain-English write-ups of both live in `docs/`.
- **`cli_utils.py`** — cross-cutting CLI helpers used by nearly every script: `use_utf8_output()`, called first in every script's `main()` so piped output is UTF-8 on Windows too (without it, non-cp1252 characters crash the script), `die(message, as_json)` for uniform error-exit, `validate_url_scheme(url, as_json)` for the `http://`/`https://` check shared by the four `url_*.py` scripts, `response_text(response)` for decoding a fetched page correctly when the server names no charset (used by `url_content.py`, `url_links.py`, `url_metadata.py`), `positive_int` / `non_negative_int` / `bounded_int(maximum)` argparse types, `load_dotenv()` for `.env`-based API key loading, `require_env(name, script, as_json)` for the API-key check, `raise_for_status(response)` (keeps the provider's own error reason, e.g. Brave's `SUBSCRIPTION_TOKEN_INVALID`, that requests' `raise_for_status()` drops) and `redact(message, secret)` (keeps API keys out of error messages; SerpApi's key is in its request URL), both used by the keyed `web_search_*.py` scripts (scripts call `load_dotenv()` first, keeping it patchable in tests), and `format_result()`/`print_results()` for the shared `{rank, title, url, snippet}` shape used by six of the seven `web_search_*.py` scripts (all but `web_search_perplexity.py`).
- **`robots.py`** — reads a site's robots.txt by RFC 9309 (longest match wins; not `urllib.robotparser`, which takes the first) and its `Content-Signal` lines; behind `url_content.py --respect-robots`, which refuses a page that is disallowed, opted out of AI input (`ai-input=no`), or whose robots.txt can't be read. **Any agent that chooses URLs itself (rather than being handed them by the user) must pass `--respect-robots`**; `hottest-tech-discussion-summary` does. `url_feed.py` has the same `--respect-robots` / `--warn-robots` pair (checking a page and the feed it advertises); the `url-feed` agent passes `--warn-robots` for a URL the user gave and `--respect-robots` when it picks a site's URL itself. `url_broken_links.py` reads each linked host's robots.txt once and skips the links it disallows (the page itself, the user's choice, is only reported on, warn-style). Agents fetching a URL the user gave pass `--warn-robots` instead (fetch regardless; report an `ai-input=no` opt-out in `ai_input_warning` and a disallowing rule in the softer `robots_disallow_note`); `url-content` and `url-summary` do.
- **`stock_tech_buzz_agent.py`** and **`app/hottest_discussions/hottest_discussions_server.py`** import `market_top_volume.py` / `hottest_tech_discussions.py` directly rather than shelling out, for the same reason. Likewise **`app/stock_information/stock_info_server.py`** imports `yahoo_finance.py`, `stock_price_history.py`, `stock_intrinsic_value.py` and `stock_fundamental.py` (which itself reuses `stock_intrinsic_value.py`'s fetch and parsing). Both apps are small `http.server` servers (default ports 8000 and 8001) so their pages run the repo's Python instead of re-implementing it in JavaScript. **`url_content.py`** imports `url_metadata.extract_metadata()` for its `--text` `title`, so the two scripts read titles by the same rules.

When adding a new script that overlaps an existing one, prefer extending the shared module over copy-pasting — that's the established pattern here.

### The `--json` convention

Every CLI script that an agent calls supports a `--json` flag: with it, the leading human progress line is suppressed and the result prints as a single JSON object/array on stdout; without it, a formatted human-readable report prints instead. **On failure, the exit code is 1 and the error goes to stderr** — as `{"error": "..."}` with `--json`, or a plain `Error: ...` line otherwise. Argparse-level failures (bad flag values, mutually exclusive flags used together) exit with code **2** instead, before any network call. This split (1 = runtime/data failure via `cli_utils.die()`, 2 = argument-parsing failure) is load-bearing for the test suite and for how agents decide whether to retry.

### Agent layer (`.claude/agents/*.md`)

Each subagent is a thin conversational wrapper around exactly one (or a small, fixed chain of) underlying script(s), invoked via the `Bash` tool with `--json`, parsing stdout, and reporting a summary — never fabricating data the script didn't return. Conventions to preserve when adding or editing an agent:
- Frontmatter `tools:` is scoped to the minimum needed (`Bash` alone for most; `Bash, Read` for the two chart agents, which also read back the generated PNG to confirm it rendered).
- Frontmatter `model:` is the smallest that fits the agent's judgement: `haiku` for one script run and reported (the four weather / air-quality agents, `url-availability`, `url-links`, `url-metadata`, `url-content`, `hottest-tech-discussions`), `sonnet` for bounded judgement (ticker resolution, date wording, robots choices, summaries). `hottest-tech-discussion-summary`, `hn-search` and `stock-intrinsic-value` set none and run on the session's model, as do `web-search` and `package-vulnerabilities`, which failed test-run cases on Sonnet on 2026-10-22. After changing an agent's model, rerun its `test-runs.md` cases if it has them.
- A "no location/ticker found"-type result is reported as-is; a transient-looking network failure is retried **at most once**.
- Chart agents always render to an explicit `/tmp/...` path (never `--show`, never writing into the repo) and return the absolute PNG path on its own line for the caller to display.
- The `web-search` agent chains through six `web_search_*.py` scripts in a fixed fallback order (Brave → Serper → Tavily → SerpApi → Exa → DuckDuckGo) based on which API key is present/working, stopping at the first success; `web_search_perplexity.py` is deliberately excluded from that chain because its output shape (synthesized answer + sources) doesn't match the others' flat `[{rank, title, url, snippet}, ...]`.
- Subagent definitions are loaded at session start — a new or edited `.claude/agents/*.md` file only takes effect in sessions started **after** the edit, not the current one.

### Test layer (`tests/`)

Fully offline: every HTTP call is monkeypatched at the seam closest to the boundary (e.g. `monkeypatch.setattr(yf.requests, "get", ...)`, `monkeypatch.setattr(weather, "fetch_json", ...)`). `tests/helpers.py` provides `FakeResponse`/`FakeSession` duck-types of `requests.Response`/`requests.Session`; `tests/conftest.py` holds the shared `chart_result` fixture (a well-formed Yahoo chart `result` block). Test files mirror module names 1:1 (`foo.py` → `tests/test_foo.py`), grouped into `class Test<Thing>` per behavior. `main()` is tested by calling it directly with an argv list and asserting on `capsys` + `SystemExit.code`, not by spawning a subprocess. Agents, being prompts, aren't covered by the suite; the multi-step `hottest-tech-discussion-summary` agent, the `web-search` agent's fallback rules and the `url-summary`, `hn-search`, `trip-weather`, `url-feed` and `package-vulnerabilities` agents' judgement rules instead have targeted live runs in `docs/features/agent/<agent>/test-runs.md` (a fixed topic per edge-case rule, with pass criteria), to rerun after editing that agent and to extend when a run finds a new edge case. See `tests/README.md` for the full per-module coverage table and conventions before adding a test.

### Documentation is kept in lockstep with code

`README.md` documents every script and every agent in matching sections (Requirements / Usage / Example / How it works / Configuration / API reference / Error handling / Notes-limitations), and `tests/README.md` keeps a per-module coverage table current. When adding or changing a script, agent, or test module, update both README files in the same change — this repo's history treats that as part of the same commit, not a follow-up.

Each runnable script, agent and web app also has a feature spec in the same Requirement / Actions / `{{placeholder}}` format: `docs/features/script/<script_name>/features.md` (one per root `.py` with a CLI; the helper modules have none), `docs/features/agent/<agent-name>/features.md` (one per `.claude/agents/*.md`), and `app/<app>/docs/features.md`. The web apps were built from their specs — when asked to "update the app in .../features.md", diff the spec against the last commit and implement the change. The script and agent specs were written afterwards from the code; when a script or agent changes, update its spec in the same change. Agent specs live under `docs/` rather than `.claude/agents/` because every `.md` file there is loaded as an agent.

## Key domain notes worth knowing before touching the code

- **Yahoo Finance fails the source audit** ([`docs/source-audit.md`](docs/source-audit.md), 2026-10-20): its API hosts' robots.txt is `Disallow: /`, `finance.yahoo.com` blocks Claude agents by name, and its terms forbid automated collection. Don't build anything new on it. The four price scripts moved off it on 2026-10-21 (to `price_source.py`: EODHD, plus Alpha Vantage for India); `market_top_volume.py`, the `quoteSummary` scripts and `app/stock_information/` still use it, and replacing those is an open backlog item ([`docs/things-to-explore.md`](docs/things-to-explore.md)).
- **Yahoo Finance and the market-screener endpoints are unofficial/undocumented** (chart endpoint, screener endpoint, quoteSummary). They can change without notice; the crumb/cookie handshake (`yahoo_finance.fetch_crumb()`, used by `market_top_volume.py` and, through `fetch_quote_summary()`, by `stock_intrinsic_value.py`, `stock_fundamental.py`, `stock_earnings_calendar.py`, `stock_analyst_targets.py` and `stock_holders.py`) is the most fragile part.
- **Check a source's robots.txt and terms before adding it.** Lobsters was added on 2026-10-19 and removed the same day: its robots.txt disallows the whole site to every client except a few named search engines and declares `ai-input=no, ai-train=no`. Don't re-add it, and look for the same signals (a wildcard `Disallow: /`, AI opt-outs, API terms) before building on any new site; record the finding in `docs/things-to-explore.md` either way. [`docs/source-audit.md`](docs/source-audit.md) holds the check of every existing source; update it when a source is added or removed.
- **OSV.dev data is licensed per source**, mostly CC-BY 4.0, which requires attribution: `osv_vulnerabilities.py` names each advisory's source database and osv.dev link and ends with an attribution line, and the `package-vulnerabilities` agent ends its report with a credit line. Keep both when changing either. OSV also answers an unknown package exactly as a clean one, so neither should ever call an empty result "safe".
- **Open-Meteo's data is CC BY 4.0**: the five weather / air-quality scripts (with `trip_weather.py`) end every result with `weather.ATTRIBUTION` (and add it to the JSON as `attribution`), and their agents end with a credit line. Keep both.
- **`web_search_duckduckgo.py` must keep its backend pinned to DuckDuckGo.** `ddgs`'s default `"auto"` backend also scrapes Google, Yahoo, Startpage, Mojeek and Grokipedia against their robots.txt.
- **US AQI and European AQI are not comparable** — different breakpoints/scales; `air_quality.py` and its agent deliberately never average or combine them.
- **Tickers are Yahoo notation**, including exchange suffixes for non-US listings (`.L`, `.SI`, `.DE`, `.PA`, `.TO`, `.AX`, `.NS`, `.HK`, `.T`, …) — none of the stock scripts resolve company names to tickers themselves; that resolution happens in the agent layer's judgment. The price scripts (`stock_price_history.py`, `stock_risk.py` and the two chart scripts) also take Yahoo's non-equity symbols — indices (`^GSPC`), currency pairs (`EURUSD=X`), crypto (`BTC-USD`) — but, through `price_source.py`, not Singapore (`.SI`), Tokyo (`.T`) or futures (`=F`) for now, and their agents say so; the `quoteSummary` scripts (fundamentals, intrinsic value, earnings calendar, analyst targets, holders) only make sense for company stocks.
- **`indicators.py`/`valuation.py` outputs are descriptive/mechanical, not predictive** — `trend()` is a straight-line fit, DCF/multiple valuations are pure arithmetic over caller-supplied assumptions. Don't let agent-facing text overstate them as forecasts or advice.
